# 学校教务系统数据库设计实验（修订版）

## 一、需求分析

学校中有若干**系**，每个系有若干**班级**和**教研室**；每个教研室有若干**教员**；**学生**分为本科生和研究生；**教员**中包含**教授**；**教授**可以指导若干**研究生**，且教授只能指导研究生、研究生只能由教授指导；每个班有若干学生；每个学生选修若干**课程**，每门课程可由若干学生选修。

## 二、概念模型（E-R 图）

* 实体：系、班级、教研室、教员、学生、课程
* 特殊化（ISA）：
  * 学生 ⊇ {本科生, 研究生}
  * 教员（按职称）⊇ {教授, 其他教员}
* 联系：
  * 系 —拥有→ 班级（1 : n）
  * 系 —下设→ 教研室（1 : n）
  * 教研室 ←属于— 教员（1 : n）
  * 班级 —组成→ 学生（1 : n）
  * 学生 ←选修→ 课程（m : n，联系属性：成绩）
  * **教授 —指导→ 研究生（1 : n）**　← 该联系连接的是两个**子类**，不是教员和学生两个总体

E-R 图见 `E-R图.html`（浏览器打开查看，可截图/打印）。

## 三、数据库逻辑结构设计

转换规则：
* 每个实体转换为一个关系模式；
* 1:n 联系并入 n 端关系，加入 1 端主码作为外码；
* m:n 联系（选修）单独转换为一个关系模式，主码由双方主码组合；
* 特殊化/普遍化：超类（学生、教员）各建一表并加“类别/职称”判别属性；子类中只需存放**子类特有**的信息——研究生单独建表存放“指导教员工号”，其学号既是主码又是参照学生的外码。

### 关系模式（下划线为主码，* 为外码）

1. **系**（<u>系编号</u>，系名）
2. **班级**（<u>班级编号</u>，班级名，*系编号*）
3. **教研室**（<u>教研室编号</u>，名称，*系编号*）
4. **教员**（<u>工号</u>，姓名，职称，*教研室编号*）　—— 职称 ∈ {教授, 副教授, 讲师, …}
5. **学生**（<u>学号</u>，姓名，性别，年龄，*班级编号*，类别）　—— 类别 ∈ {本科生, 研究生}
6. **研究生**（<u>学号</u>，研究方向，*指导教员工号*）　—— 学号参照学生；指导教员工号参照教员，**且该教员职称必须为教授**
7. **课程**（<u>课程号</u>，课程名，学分）
8. **选修**（<u>学号</u>，<u>课程号</u>，成绩）　—— 学号参照学生，课程号参照课程

### SQL 建表语句（参考）

```sql
CREATE TABLE Dept (                     -- 系
    DeptNo   CHAR(4) PRIMARY KEY,
    DeptName VARCHAR(30) NOT NULL
);

CREATE TABLE Class (                    -- 班级
    ClassNo   CHAR(8) PRIMARY KEY,
    ClassName VARCHAR(30) NOT NULL,
    DeptNo    CHAR(4) NOT NULL,
    FOREIGN KEY (DeptNo) REFERENCES Dept(DeptNo)
);

CREATE TABLE ResearchOffice (           -- 教研室
    RONo   CHAR(6) PRIMARY KEY,
    ROName VARCHAR(30) NOT NULL,
    DeptNo CHAR(4) NOT NULL,
    FOREIGN KEY (DeptNo) REFERENCES Dept(DeptNo)
);

CREATE TABLE Teacher (                  -- 教员（职称用于区分子类“教授”）
    TNo    CHAR(6) PRIMARY KEY,
    TName  VARCHAR(20) NOT NULL,
    Title  VARCHAR(10) NOT NULL,        -- 教授/副教授/讲师…
    RONo   CHAR(6) NOT NULL,
    FOREIGN KEY (RONo) REFERENCES ResearchOffice(RONo)
);

CREATE TABLE Student (                  -- 学生（超类，类别判别属性）
    SNo     CHAR(10) PRIMARY KEY,
    SName   VARCHAR(20) NOT NULL,
    Sex     CHAR(2),
    Age     SMALLINT,
    ClassNo CHAR(8) NOT NULL,
    SType   VARCHAR(6) NOT NULL,        -- '本科生' / '研究生'
    FOREIGN KEY (ClassNo) REFERENCES Class(ClassNo)
);

CREATE TABLE Graduate (                 -- 研究生（子类表，只存特有信息）
    SNo      CHAR(10) PRIMARY KEY,     -- 既是主码又参照学生
    Field    VARCHAR(30),              -- 研究方向
    AdvisorTNo CHAR(6) NOT NULL,       -- 指导教员工号，必须是教授
    FOREIGN KEY (SNo) REFERENCES Student(SNo),
    FOREIGN KEY (AdvisorTNo) REFERENCES Teacher(TNo)
);

CREATE TABLE Course (                   -- 课程
    CNo    CHAR(6) PRIMARY KEY,
    CName  VARCHAR(30) NOT NULL,
    Credit SMALLINT
);

CREATE TABLE SC (                       -- 选修（m:n 联系）
    SNo   CHAR(10),
    CNo   CHAR(6),
    Grade SMALLINT,
    PRIMARY KEY (SNo, CNo),
    FOREIGN KEY (SNo) REFERENCES Student(SNo),
    FOREIGN KEY (CNo) REFERENCES Course(CNo)
);
```

**“指导教员必须为教授”的约束**：多数 DBMS 的 CHECK 不支持子查询，可用触发器实现，例如：

```sql
-- SQL Server 语法示例
CREATE TRIGGER trg_AdvisorMustBeProfessor
ON Graduate FOR INSERT, UPDATE
AS
IF EXISTS (SELECT 1 FROM inserted i
           JOIN Teacher t ON t.TNo = i.AdvisorTNo
           WHERE t.Title <> '教授')
    ROLLBACK TRANSACTION;
```

## 四、设计要点

* “教授只指导研究生、研究生只由教授指导”体现在：
  1. 概念模型上，“指导”菱形连接的是**教授**与**研究生**两个子类（通过 ISA 三角与超类相连）；
  2. 逻辑模型上，`Graduate` 表的主码即学生的学号（只有研究生才出现在该表中），其外码 `AdvisorTNo` 通过触发器/CHECK 保证指向职称为“教授”的教员。
* “选修”为 m:n 联系，单独建表，主码为（学号，课程号），并记录“成绩”。
* 其余 1:n 联系（拥有、下设、属于、组成）均通过在 n 端关系中加入 1 端主码作外码实现。
